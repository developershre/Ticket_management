# Ticket Management System (TMS) API – Complete Reference

**API version:** `v1`  
**Transport:** HTTPS  
**Method:** `POST`  
**Content-Type:** `application/json`  
**Backend:** Google Apps Script Web App  
**Data store:** Google Sheets

This guide documents the API actions present in the TMS `API.gs` source and the Postman collection. All requests use the same Web App `/exec` URL.

---

## 1. Configure the API

### 1.1 Web App URL

Deploy the Apps Script project as a Web App and copy its `/exec` URL:

```text
https://script.google.com/macros/s/YOUR_DEPLOYMENT_ID/exec
```

### 1.2 Generate an API key

Run `generateTMSApiKey()` once from the Apps Script editor. Copy the generated key from the execution log and store it securely. The project stores its SHA-256 hash, not the plain key. Do not share the key publicly or commit it to source control.

### 1.3 Common request structure

Except for `health.check`, include `auth.api_key`:

```json
{
  "version": "v1",
  "action": "tickets.list",
  "auth": {
    "api_key": "YOUR_API_KEY"
  },
  "request_id": "optional-client-request-id",
  "data": {}
}
```

`request_id` is optional. It is useful for tracing requests in logs. `data` contains the action-specific fields.

### 1.4 Health check (no API key)

**Action:** `health.check`

```json
{
  "version": "v1",
  "action": "health.check",
  "data": {}
}
```

This checks that the API is responding and returns the active spreadsheet name.

## 2. Tickets API

### 2.1 Create ticket

**Action:** `tickets.create`  
**Required fields:** `employee_code`, `category`, `subject`  
The employee code must exist in the Employee sheet. Ticket ID and timestamps are generated by the server.

```json
{
  "version": "v1",
  "action": "tickets.create",
  "auth": { "api_key": "YOUR_API_KEY" },
  "data": {
    "employee_code": "EMP001",
    "email_address": "employee@example.com",
    "category": "IT Support",
    "subject": "Laptop is not connecting to Wi-Fi",
    "problem_description": "The laptop connects but shows no internet access.",
    "priority": "High",
    "assigned_to": "IT Helpdesk",
    "customer": "Aarav Sharma",
    "status": "Open",
    "stage": "New",
    "kanban_state": "To Do"
  }
}
```

Other accepted optional fields: `attachment_name`, `attachment_url`, `time_spent`, `activities_text`, `my_activity`, `deadline`, `sla_status`, `sla_deadline`, `rating_avg_text`.

### 2.2 Get one ticket

**Action:** `tickets.get`  
**Required:** `ticket_id`

```json
{
  "version": "v1",
  "action": "tickets.get",
  "auth": { "api_key": "YOUR_API_KEY" },
  "data": {
    "ticket_id": "TKT-2026-000001"
  }
}
```

### 2.3 List tickets

**Action:** `tickets.list`  
**Optional exact filters:** `employee_code`, `status`, `priority`, `assigned_to`, `category`  
**Optional search:** `query` searches ticket ID, subject, problem description, customer, employee code and email.  
**Pagination:** `offset` (default `0`), `limit` (default `50`, maximum `200`).

```json
{
  "version": "v1",
  "action": "tickets.list",
  "auth": { "api_key": "YOUR_API_KEY" },
  "data": {
    "status": "Open",
    "priority": "High",
    "query": "network",
    "offset": 0,
    "limit": 50
  }
}
```

### 2.4 Update ticket

**Action:** `tickets.update`  
**Required:** `ticket_id` plus at least one field to update. Send only the fields that should change.

```json
{
  "version": "v1",
  "action": "tickets.update",
  "auth": { "api_key": "YOUR_API_KEY" },
  "data": {
    "ticket_id": "TKT-2026-000001",
    "status": "In Progress",
    "assigned_to": "EMP010",
    "priority": "Medium"
  }
}
```

The update action accepts the ticket creation fields listed in section 2.1 (except generated `ticket_id`, which is supplied separately). `last_updated_on` is updated by the server.

### 2.5 Delete ticket

**Action:** `tickets.delete`  
**Required:** `ticket_id`

```json
{
  "version": "v1",
  "action": "tickets.delete",
  "auth": { "api_key": "YOUR_API_KEY" },
  "data": {
    "ticket_id": "TKT-2026-000001"
  }
}
```

**Warning:** This permanently deletes the ticket row from the Tickets sheet. It is not an archive operation.

## 3. Employees API

The Employee sheet is read using recognized header names, so supported columns can be in a different order and may use common header variants. The API returns the normalized fields shown below.

### 3.1 Create employee

**Action:** `employees.create`  
**Required:** `employee_code`, `employee_name`  
**Optional:** `department`, `email`, `division`  
`employee_code` must be unique.

```json
{
  "version": "v1",
  "action": "employees.create",
  "auth": { "api_key": "YOUR_API_KEY" },
  "data": {
    "employee_code": "EMP001",
    "employee_name": "Aarav Sharma",
    "department": "IT",
    "email": "employee@example.com",
    "division": "Corporate"
  }
}
```

### 3.2 Get employee

**Action:** `employees.get`  
**Required:** `employee_code`

```json
{
  "version": "v1",
  "action": "employees.get",
  "auth": { "api_key": "YOUR_API_KEY" },
  "data": {
    "employee_code": "EMP001"
  }
}
```

### 3.3 List/filter employees

**Action:** `employees.list`  
**Optional exact filters:** `department`, `division`  
**Optional search:** `query` searches employee code, name, department, email and division. This action returns all matches; the current implementation does not paginate this endpoint.

```json
{
  "version": "v1",
  "action": "employees.list",
  "auth": { "api_key": "YOUR_API_KEY" },
  "data": {
    "department": "IT",
    "division": "Corporate",
    "query": "Aarav"
  }
}
```

### 3.4 List all employees (ignore division and department)

**Action:** `employees.listAll`  
**Data:** `{}`  
Returns all employee rows with an employee code, regardless of division or department. This action does not paginate.

```json
{
  "version": "v1",
  "action": "employees.listAll",
  "auth": { "api_key": "YOUR_API_KEY" },
  "data": {}
}
```

### 3.5 Update employee

**Action:** `employees.update`  
**Required:** `employee_code` and at least one field to update. Accepted update fields: `employee_name`, `department`, `email`, `division`.

```json
{
  "version": "v1",
  "action": "employees.update",
  "auth": { "api_key": "YOUR_API_KEY" },
  "data": {
    "employee_code": "EMP001",
    "department": "Information Technology",
    "email": "aarav@example.com"
  }
}
```

### 3.6 Delete employee

**Action:** `employees.delete`  
**Required:** `employee_code`

```json
{
  "version": "v1",
  "action": "employees.delete",
  "auth": { "api_key": "YOUR_API_KEY" },
  "data": {
    "employee_code": "EMP001"
  }
}
```

Deletion is blocked if a ticket references the employee code. This endpoint permanently deletes the employee row when it is not referenced by a ticket.

### Employee response shape

```json
{
  "employee_code": "EMP001",
  "employee_name": "Aarav Sharma",
  "department": "IT",
  "email": "employee@example.com",
  "division": "Corporate"
}
```

## 4. Reminders API

Reminder creation stores a row in the Reminders sheet. If `send_at` is in the past or present, the API attempts to send immediately. If it is in the future, it remains scheduled for the time-driven reminder processor. Install/authorize the reminder trigger in Apps Script for scheduled delivery.

### 4.1 Create reminder (with optional CC)

**Action:** `reminders.create`  
**Required:** `employee_code`, `service_category`, `reminder_message`, `send_at`  
**Optional:** `cc_emails` (array or comma/semicolon-separated string); legacy alias `cc` is also accepted.

```json
{
  "version": "v1",
  "action": "reminders.create",
  "auth": { "api_key": "YOUR_API_KEY" },
  "data": {
    "employee_code": "EMP001",
    "service_category": "IT Support",
    "reminder_message": "Please raise a ticket if your laptop/network issue is still unresolved.",
    "send_at": "2026-12-01T10:00:00+05:30",
    "cc_emails": [
      "it.manager@example.com",
      "supervisor@example.com"
    ]
  }
}
```

For no CC, omit `cc_emails` or pass an empty array. Use ISO 8601 with an explicit timezone offset, for example `2026-12-01T10:00:00+05:30` for India Standard Time.

The response contains the saved `reminder` and a `delivery` object. For a future reminder, `delivery.status` is `scheduled`. For an immediately due reminder, inspect `delivery.email_sent`, `delivery.status`, and any `delivery.error`.

### 4.2 Get one reminder

**Action:** `reminders.get`  
**Required:** `reminder_id`

```json
{
  "version": "v1",
  "action": "reminders.get",
  "auth": { "api_key": "YOUR_API_KEY" },
  "data": {
    "reminder_id": "REM-20261103103000-ABC12345"
  }
}
```

### 4.3 List reminders

**Action:** `reminders.list`  
**Optional exact filters:** `employee_code`, `status`, `service_category`  
**Optional search:** `query` searches reminder ID, employee code/name/email, category, message and ticket ID.  
**Pagination:** `offset` (default `0`), `limit` (default `50`, maximum `200`).

```json
{
  "version": "v1",
  "action": "reminders.list",
  "auth": { "api_key": "YOUR_API_KEY" },
  "data": {
    "status": "Pending",
    "employee_code": "EMP001",
    "offset": 0,
    "limit": 50
  }
}
```

### 4.4 Update reminder

**Action:** `reminders.update`  
**Required:** `reminder_id` plus at least one field to update. Accepted fields: `employee_code`, `service_category`, `reminder_message`, `send_at`, `status`, `cc_emails` (or `cc`).

```json
{
  "version": "v1",
  "action": "reminders.update",
  "auth": { "api_key": "YOUR_API_KEY" },
  "data": {
    "reminder_id": "REM-20261103103000-ABC12345",
    "reminder_message": "Please create a ticket for the pending network issue.",
    "send_at": "2026-12-02T11:30:00+05:30",
    "status": "Pending",
    "cc_emails": ["it.manager@example.com"]
  }
}
```

Allowed status values are `Pending` and `Cancelled`. `Completed` is managed by the system and cannot be set through this API. Completed reminders cannot be updated. To clear CC recipients, send `"cc_emails": []` or `"cc_emails": ""`.

### 4.5 Send reminder now

**Action:** `reminders.sendNow`  
**Required:** `reminder_id`  
**Optional:** `force` (boolean, default `false`).

```json
{
  "version": "v1",
  "action": "reminders.sendNow",
  "auth": { "api_key": "YOUR_API_KEY" },
  "data": {
    "reminder_id": "REM-20261103103000-ABC12345"
  }
}
```

To intentionally resend even if the reminder was already emailed today:

```json
{
  "version": "v1",
  "action": "reminders.sendNow",
  "auth": { "api_key": "YOUR_API_KEY" },
  "data": {
    "reminder_id": "REM-20261103103000-ABC12345",
    "force": true
  }
}
```

Only pending reminders can be sent. Without `force: true`, the API prevents sending the same reminder again on the same day.

### 4.6 Reminder digest email behavior

The reminder sender groups due pending reminders for the **same employee**. When the eligible group contains **more than five** reminders (six or more), it sends one digest email with an individual secure ticket-form link for each reminder. Five or fewer eligible reminders are sent individually. CC recipients are included on the corresponding reminder email/digest according to the reminder sender implementation. Reminders for different employees are never grouped together.

## 5. Standard response formats

### Successful response

```json
{
  "success": true,
  "data": {
    "example": "result"
  },
  "message": "Request completed.",
  "server_timestamp": "2026-11-03T05:38:28.068Z",
  "request_id": "optional-client-request-id"
}
```

The actual `data` shape depends on the action. List actions return `items` and either `pagination` or `total` as described above.

### Error response

```json
{
  "success": false,
  "data": null,
  "message": "A human-readable error message.",
  "error": {
    "code": "ERROR_CODE",
    "retryable": false,
    "details": null
  },
  "server_timestamp": "2026-11-03T05:38:28.068Z",
  "request_id": "optional-client-request-id"
}
```

Common error codes include `EMPTY_BODY`, `REQUEST_TOO_LARGE`, `UNSUPPORTED_VERSION`, `API_NOT_CONFIGURED`, `UNAUTHORIZED`, `UNKNOWN_ACTION`, `VALIDATION_ERROR`, `NOT_FOUND`, `ALREADY_EXISTS`, `CONFLICT`, `EMPLOYEE_NOT_FOUND`, `EMPLOYEE_EMAIL_INVALID`, `SCHEMA_MISMATCH`, and `INTERNAL_ERROR`.

## 6. Limits and operational notes

- All API actions use `POST` with JSON to the same `/exec` URL.
- API version must be exactly `v1`.
- Request body maximum is 45,000 characters in the current API configuration.
- List endpoints that paginate use a maximum `limit` of 200.
- `health.check` is the only action that does not require an API key.
- Do not send the API key in query parameters. Send it in `auth.api_key` in the JSON body.
- For scheduled reminder delivery, the Apps Script time-driven trigger and email authorization must be installed in the Apps Script project.
- API calls that create or update records should not be blindly retried after an ambiguous network timeout; first query the relevant record/list to avoid accidental duplicates.
- `tickets.delete` and `employees.delete` are destructive operations.

## 7. Postman setup

Create a Postman collection with these variables:

| Variable | Value |
|---|---|
| `base_url` | Your deployed Apps Script `/exec` URL |
| `api_key` | The key printed by `generateTMSApiKey()` |
| `reminder_id` | A real Reminder ID returned by `reminders.create` |

For every request, use:

- Method: `POST`
- URL: `{{base_url}}`
- Header: `Content-Type: application/json`
- Body: `raw` → `JSON`

Replace all sample employee codes, ticket IDs, reminder IDs and email addresses with values that exist in your spreadsheet before running write/delete/send operations.
